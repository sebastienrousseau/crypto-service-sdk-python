# AGENTS.md

`crypto-service-sdk-python` is the Python client for the crypto-server
REST API. The Crypto Service suite has one engine, crypto-server, and
thin typed clients per language, all proven by one conformance kit
vendored from crypto-service. This repository's value is that a Python
caller gets the behaviour the kit pins, with typed results, async and
blocking, and no cryptography of its own. Read
[CONTRIBUTING.md](CONTRIBUTING.md) and [DEVELOPMENT.md](DEVELOPMENT.md)
as well.

## Rules

- **Version.** `0.0.x`, moving by exactly `0.0.1`, in lockstep with the
  Crypto Service suite; never propose a jump. The version lives once, in
  `pyproject.toml`; when it moves, every file
  `scripts/verify-release-versions` lists moves with it (`uv.lock`,
  `CITATION.cff`, the README install command, the SECURITY and SUPPORT
  tables, the bug template) and `CHANGELOG.md` gets the new
  `## [0.0.N] - Unreleased` heading. Work for the next version happens on
  `feat/v<next-version>`; every other branch, Dependabot's included,
  merges into that branch, never into `main`.
- **`conformance/` is vendored from crypto-service, never edit it here.**
  It is replaced as a whole at the commit named in `ci/server.ref`, and
  `tests/test_conformance.py` checks its `SHA256SUMS` on every run.
- **Thin client.** No cryptography in the SDK
  ([ADR 0001](docs/adr/0001-thin-client-over-the-server.md)): every
  operation is an HTTP call to crypto-server.
- **Never log or expose secrets.** No credential, key, plaintext, request
  or response body, or problem `detail` in a log, an exception message,
  `repr` or debug output.
- **Edit the async source only.** `src/crypto_service/_sync/` is
  generated by `make unasync`; CI fails when it is stale.
- **Gates.** `make check` must pass: versions, generated client, ruff
  lint and format, `mypy --strict`, complexity (cyclomatic 10, cognitive
  15, Halstead difficulty 30, 60 lines per function, 500 lines per file;
  `scripts/complexity-baseline.json` is empty and only shrinks), and 100%
  line and branch coverage. No blanket suppressions.
- **Commits.** Conventional, signed off (`git commit -s`), SSH-signed,
  with an `Assisted-by:` trailer for agent work. Never rewrite pushed
  history; never merge into `main` without the maintainer.
- **Data.** Synthetic keys and credentials only.

## The gate

```sh
make check        # the local gate
make regression   # everything, against a crypto-server it starts and stops
```

## Leave alone

`conformance/`, `LICENSE*`, `LICENSES/`, `DCO.txt`, the generated
`src/crypto_service/_sync/` and the recorded responses in
`benchmarks/responses/`, unless the task is to update them.
